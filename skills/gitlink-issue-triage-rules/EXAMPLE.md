# 示例一：在个人仓库上分拣 Issue

> 完整运行记录：[WorkBuddy 任务链接](https://codebuddy.work/agents/tasks/share/1OyFJtnSag?platform=workbuddy)

## 场景说明

在自己有管理权限的 GitLink 仓库上，使用本 Skill 自动完成 Issue 分类、打标签、分配责任人和设置优先级。

## 运行环境

| 项目 | 内容 |
|------|------|
| **后端** | GitLink（gitlink-cli） |
| **目标仓库** | [Angel123456/gitlink-cli](https://www.gitlink.org.cn/Angel123456/gitlink-cli) |
| **运行模式** | `hybrid`（规则优先 + LLM 兜底） |
| **规则数量** | 3 条（bug-default / question-default / docs-typo） |
| **涉及 Issue** | 4 条（全部无标签、无责任人） |

## 分拣前状态

4 条 Issue 均为未分拣状态：

| # | 标题 | 标签 | 责任人 |
|---|------|------|--------|
| #4 | 服务启动时偶尔会崩溃 | 无 | 无 |
| #5 | 建议支持 JSON 格式日志输出 | 无 | 无 |
| #6 | 请问如何配置多环境变量？ | 无 | 无 |
| #7 | 建议支持 Markdown 格式的评论 | 无 | 无 |

## dry-run 预览

Agent 完成规则评估后输出预览，**此阶段未修改任何 Issue**：

| # | 标题 | 建议标签 | 责任人 | 优先级 | 命中规则 |
|---|------|----------|--------|--------|----------|
| #4 | 服务启动时偶尔会崩溃 | 缺陷 | Angel123456 | 高 | bug-default |
| #5 | 建议支持 JSON 格式日志输出 | 功能 | Hsy15889521073 | 正常 | LLM兜底 |
| #6 | 请问如何配置多环境变量？ | 疑问 | Priziq | 正常 | question-default |
| #7 | 建议支持 Markdown 格式的评论 | 重复 | Hsy15889521073 | 低 | LLM兜底(重复检测) |

## 执行写回

用户确认后，Agent 按工作流执行：

1. **回读**：每条 Issue 先 `view` 获取当前标题和正文
2. **PATCH**：写入 `issue_tag_ids` + `assigner_ids` + `priority_id`，同时带回标题和正文防止清空
3. **审计评论**：记录命中规则和关键词

## 验证结果

|---|------|------|--------|--------|----------|----------|
| #4 | 服务启动时偶尔会崩溃 | ✅ 缺陷 | ✅ Angel123456 | ✅ 高 | ✅ | ✅ |
| #5 | 建议支持 JSON 格式日志输出 | ✅ 功能 | ✅ Hsy15889521073 | ✅ 正常 | ✅ | ✅ |
| #6 | 请问如何配置多环境变量？ | ✅ 疑问 | ✅ Priziq | ✅ 正常 | ✅ | ✅ |
| #7 | 建议支持 Markdown 格式的评论 | ✅ 重复 | ✅ Hsy15889521073 | ✅ 低 | ✅ | ✅ |

## 执行统计

| 指标 | 数据 |
|------|------|
| 涉及 Issue | 4 条 |
| 规则命中 | 2 条（bug-default / question-default） |
| LLM 兜底 | 2 条（功能需求 / 重复检测） |
| API 调用 | 12 次（全部成功） |
| 人工干预 | 仅确认 dry-run + 指定责任人 |
| 总耗时 | 约 2 分钟 |

# 示例二：在他人仓库上分拣 Issue

> 完整运行记录：[WorkBuddy 任务链接](https://codebuddy.work/agents/tasks/share/mmnw7Ov594?platform=workbuddy)

## 场景说明

在他人仓库上运行 Skill，演示**权限受限场景**下的适配能力：
- 无法获取成员列表（403）→ 跳过责任人分配
- 仍可执行打标签、设优先级、添加审计评论
- 体现 Skill 在开源社区协作场景中的实用性

## 运行环境

| 项目 | 内容 |
|------|------|
| **后端** | GitLink（gitlink-cli） |
| **目标仓库** | [Gitlink/gitlink-cli](https://www.gitlink.org.cn/Gitlink/gitlink-cli)（官方主仓库） |
| **当前用户** | Angel123456（非仓库成员） |
| **运行模式** | `hybrid`（规则优先 + LLM 兜底） |

| 查询标签列表 | ✅ 成功 | 正常获取 10 个中文标签 |

## 关键结论

即使在**无管理权限**的他人仓库上，Skill 仍然能够：
1. 正常读取 Issue 列表和标签列表
2. 完成规则评估和 dry-run 预览
3. 成功执行打标签、设置优先级、添加审计评论
4. 优雅处理权限不足的情况，不阻塞整体流程

这证明了 Skill 在**开源社区协作场景**（如帮助其他项目维护者分类 Issue）中的实用价值。
